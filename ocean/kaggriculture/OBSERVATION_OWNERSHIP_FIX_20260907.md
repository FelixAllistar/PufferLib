Follow-up: PSRO **analysis** now uses explicit per-checkpoint layouts via native
GPU cohorts; see `PSRO_OBSERVATION_VERSIONS_20260908.md`. League admission and
submission export still require the version-aware handoff described below.

The remote next-run configuration is still the single
`/workspace/PufferLib/config/kaggriculture.ini`:

```
base.run_id = expansion4_obs1_20260907
base.load_model_path = None
env.observation_version = 1
env.frozen_observation_version = 0
selfplay.opponent_pool_prob = 1
```

Rewards, LR, entropy, batch sizes, horizons, and opponents were not changed in
this follow-up. The previous growth diagnostic settings remain. The new run ID
avoids mixing checkpoints from the already-launched legacy-layout probe with
the repaired input semantics. No trainer or production build was started or
stopped by this change. Local `config/kaggriculture.ini` remains untouched.

## Behavior

- Version **0** preserves the old absolute player-0/player-1 farm blocks.
  It remains the default for unversioned existing configurations/checkpoints.
- Version **1** puts **own farm first, opponent farm second**, just like cash,
  stocks, and worker views. It fixes the reproduced ownership collision.
- `frozen_observation_version=-1` means inherit the learner's version; setting
  it to 0 keeps the current legacy league on its original inputs. Live mirror
  opponents use the learner's version because both have policy-bank ID zero.
- New learner snapshots cannot enter old-layout frozen banks. Mixed layouts
  require a nonempty external pool and external selection probability 1;
  the trainer rejects an unsafe mixture instead of silently misinterpreting it.
- End-of-training evaluation associates versions with the models, swaps them
  for the reverse-seat match, uses version 1 for the new run's rolling
  checkpoints, and restores the configured versions afterward.
- CPU and CUDA configuration/reset paths carry the same two fields. The shared
  observation writer handles the actual farm permutation. No new model weights,
  features, network branches, or action heads were introduced. Only the two
  132-byte farm blocks swap for a version-1 actor in physical seat 1; the
  1280-byte observation and 1058-logit action ABI retain their sizes.

Do not infer a checkpoint's version from its byte count: the weight format has
not changed. Keep the run's logged configuration with its weights. Old raw-BC
observation datasets and old EMAG anchors were not upgraded by this fix.
Native state-bank snapshots remain usable because their observations are
regenerated by the configured writer.

This patch covers native training and its two-seat selfplay evaluation. The
generic PSRO population matrix and legacy offline/submission readers do not yet
have per-checkpoint version metadata. Do not put new and old observation
versions into an unversioned population matrix, or assume an old exporter has
automatically upgraded a checkpoint. Wire explicit versions into that workflow
before promoting/submitting this new lineage. Existing checkpoints and their
current standalone exports are untouched.

## Tests

`make -C ocean/kaggriculture observation-test` runs CPU checks for primitive,
legacy macro, and structured macro actions:

- the original collision in version 0 and its removal in version 1;
- invariance under swapping player identities/seats;
- exact preservation of non-farm bytes and the legacy bank's full observation;
- both learner seats, inherited versions, and live mirror self-play;
- no opponent-private stock leak;
- external versus rolling evaluation opponents, reverse-seat version swapping,
  configuration restoration, and rejection of unsafe pool mixtures.

These checks passed against both the local adapter and the separately patched
Vast adapter. The source bases differ; only the focused changes were applied
to Vast, not the unrelated local mode-3 work. The CUDA adapter test now covers
legacy, corrected, and mixed observation layouts with alternating learner
seats. CUDA/production compilation and execution are left to the user's rebuild.

## Manual rebuild and launch, on Vast

```
cd /workspace/PufferLib
./build.sh kaggriculture --gpu
./puffer train kaggriculture
```

An already-running process retains the old compiled code and its launch-time
configuration. Rebuilding the file on disk does not update that process.
Optional dedicated verification after rebuilding:

```
make -C ocean/kaggriculture observation-test
make -C ocean/kaggriculture cuda-adapter
```

The correctness fix removes an unnecessary ownership ambiguity; it does not
guarantee expansion or explain every historical training plateau.
