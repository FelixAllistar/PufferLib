# Checkpoint-compatible CNN execution — 2026-09-16

Follow-up: [observation copy elision and corrected bf16 ROM-input checks](RESULTS_20260916_OBSERVATIONS.md).
The original timing measurements below are unchanged; the follow-up documents
and corrects a test-only bf16 host-observation packing error in the earlier
checkpoint comparison.

The fused CUDA encoder is now the default Retro training path. The model is
unchanged: 351,064 parameters in the same order, full-screen image plus RAM,
three convolutions, the same recurrent layers and action/value heads. Existing
CNN checkpoints load directly. Observations, rewards, controls, PPO settings,
and the CPU viewer were not changed by this optimization.

## Matched real-PPO throughput

GTX 1060 3 GB, i5-7400, bf16, CUDA graphs, 64 agents, four CPU workers,
horizon 128, minibatch 2,048, replay ratio 2, asynchronous training, seed 73,
compiled ROM CPU, full-screen wide renderer, blocking workers, and
`OMP_WAIT_POLICY=PASSIVE` for both executables. The GPU was idle before each
comparison. Both implementations started from the same learned checkpoint;
all benchmark outputs went to private temporary directories.

Each comparison ran old/new/new/old (ABBA). The first two updates and the
final drain-only update were excluded. Rates below are total measured steps
divided by total measured seconds, not averages of dashboard rates.

| Buffers | Updates per run | Original SPS | Fused SPS | Speedup |
| --- | ---: | ---: | ---: | ---: |
| 4 | 10 | 3,753 | 13,102 | 3.49x |
| 1 | 20 | 3,968 | 13,213 | 3.33x |

Four-buffer individual runs: 3,808 / 12,436 / 13,843 / 3,699 SPS, with
57,344 measured decisions per run. One-buffer runs: 4,031 / 14,872 / 11,888 /
3,906 SPS, with 139,264 measured decisions per run. One buffer did not show a
consistent advantage, so the user's four-buffer configuration was preserved.
The matched baseline is faster than the earlier 2.3K dashboard sample; the
speedup claim uses the matched measurements, not that earlier sample.

These are short throughput tests, not a learning-curve comparison or a speed
guarantee for other hardware, policies, or levels.

## Encoder profile

The original path materialized a large image-patch matrix, then used generic
matrix multiplication. In particular, the long first-layer weight-gradient
reduction was poorly parallelized for this small-channel CNN.

The replacement uses fused convolution/bias/ReLU, shared-memory tiled
weight-gradient reductions split across image/spatial rows, and direct
input-gradient gathering. It preserves the original bf16 rounding points;
the split reduction accumulates float partials in a fixed order before
converting to bf16. No model compression or reduced-resolution inputs.

Isolated CUDA-graph encoder timings at a 2,048-sample training minibatch:

| Operation | Original | Fused |
| --- | ---: | ---: |
| Forward | 40.72 ms | 6.88 ms |
| Backward | 196.52 ms | 30.31 ms |
| Combined forward/backward | 233.62 ms | 36.01 ms |
| Allocated benchmark activation/input buffers | 458.00 MiB | 236.82 MiB |

The separate timings need not sum to the independently measured combined
timing. These encoder-only measurements are not end-to-end training SPS.
At rollout batches 16 and 64, forward time changed from 0.553/1.483 ms to
0.235/0.402 ms. The training workspace saves about 221 MiB at minibatch 2,048;
the full trainer's dashboard reported roughly 3.0 GB before and 2.8 GB after.

## Correctness and checkpoint safety

- All three convolutions' outputs and weight/bias/input gradients compared
  against the original implementation at batches 1, 3, 17, 33, and 2,048,
  in both float32 and production bf16.
- Float32 numerical gradient checks, CPU/GPU intermediate features, and
  complete recurrent logits/value tests through resets passed.
- The learned checkpoint was compared through both full CUDA policies on
  384 actual ROM decisions with six recurrent resets. Bf16 logits, values,
  and action probabilities were identical on this trajectory. Float32 maximum
  logit/value error was 5.73e-6; maximum probability error was 8.31e-7.
- Weight-gradient reductions differ by expected floating-point summation
  error. At batch 2,048 the largest float32 absolute difference was 1.78e-4;
  bf16 forward maps, input gradients, and bias gradients were identical in
  that test. This does not promise bit-identical future training trajectories.
- Real PPO interruption tests passed for synchronous SIGINT and asynchronous
  SIGTERM. Each saved policy reloaded for all 32 level starts.
- The installed `./puffer` loaded the learned checkpoint and completed a
  separate 4,096-decision PPO smoke test in a private output directory.

The original learned checkpoint and the user's `config/retro.ini` remained
byte-identical to their pre-test copies. Checkpoint SHA-256:
`988f14311e09d037b9e333098ed0690ccc54b2e4aef9b7dc1f453b4bc0f4e88f`.
As before, native checkpoints contain policy weights and a config sidecar,
not optimizer, recurrent, or emulator state.

## Reproduction

Build a reference executable without replacing the normal trainer/viewer:

```bash
RETRO_CNN_FUSED=0 NATIVE_OUTPUT_NAME=build/retro_reference ./build.sh retro
RETRO_CNN_FUSED=1 NATIVE_OUTPUT_NAME=build/retro_fused ./build.sh retro
python3 ocean/retro/batch/benchmark_cnn.py \
  build/retro_reference build/retro_fused PATH_TO_CNN_CHECKPOINT.bin --buffers 4
```

For production-precision validation:

```bash
RETRO_TEST_BF16=1 ./build.sh retro --encoder-test
./test_retro_encoder --large --checkpoint PATH_TO_CNN_CHECKPOINT.bin
OMP_WAIT_POLICY=PASSIVE python3 tests/test_native_retro_runtime.py ./puffer --agents 8
```

Omit `RETRO_TEST_BF16=1` to build the float32 numerical-gradient test. Run GPU
benchmarks/tests without another training job. Normal `./build.sh retro`
installs the fused default trainer plus the matching CPU viewer.
