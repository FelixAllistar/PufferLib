# ROM-block fork results — 2026-09-12

Archived crop-policy measurements, not the current full-screen configuration.
See ../README.md for current commands and full-screen performance.

## Scope

Working CPU specialization of the SMB1 ROM, with shared immutable compiled
pages and private mutable state per environment. No hand-rewritten gameplay,
observation, reward, controller or episode semantics. Untranslated instructions
continue in the reference interpreter. This is not yet a device-resident GPU
emulator, nor a certificate that QuickNES reproduces every hardware exploit.

The normal trainer executable was preserved. The new executable is
`./puffer_retro_batch`; explicitly select `env.cpu_backend=blocks`. The current
config remains `cpu_backend=reference` and preserves the user's `latest` load
and 1-1 spawn settings. The original environment-only benchmark below ran
alongside the previous trainer. It had stopped before the subsequent actual
training comparison; no active training process was paused for that comparison.

## Updated runtime: actual PPO throughput

Same i5-7400 (four cores), GTX 1060 3 GB, 1,024 environments, four workers,
one buffer, asynchronous PPO, horizon 128, minibatch 8,192, one-frame controls,
1-1 spawn, seed 73. Every run loaded the same explicit compatible policy:
`checkpoints/retro_rom/retro/1789179532454/0000000065536000.bin`.
PPO hyperparameters, policy, observations, actions and rewards were unchanged.

The baseline is the **previous ROM-block trainer**, not the slower interpreter.
The candidate adds blocking horizon handoffs, 1 KiB compiled regions with
local returns, event-bounded cached-status polling, shared expanded CHR rows,
exact policy-crop raster/replay, and observation-loop/palette reuse.
`OMP_WAIT_POLICY=PASSIVE` was set for both. Runs alternated ABBA; each performed
eight real PPO updates. Startup's double-horizon collection and the final
drain-only update were excluded, leaving 786,432 measured decisions per run.

| Training binary | Measured seconds | Training steps/sec |
| --- | ---: | ---: |
| Previous A | 30.647 | 25,661 |
| Updated B | 14.778 | 53,218 |
| Updated B | 16.258 | 48,371 |
| Previous A | 29.054 | 27,068 |

Combined: **26,346 → 50,679 steps/sec, 1.924× actual PPO throughput**.
This is a short matched throughput test on this workstation, not a learning
curve or a guaranteed speed for all levels/policies. All four final policy
files were byte-identical (SHA-256
`060c08bd7313a1980d4a59459c7b33f35e98d404719cf58105f78d647642a384`).
The final drain-only dashboard can show hundreds of thousands of SPS; that
number is deliberately excluded because it collects no new environment frames.

Raw commands, per-run logs, checkpoint sidecars, timings, and summary are in
`/tmp/retro-training-abba.f5geom18/`. The previous binary is backed up there as
`baseline_puffer_retro_batch`; temporary artifacts are local, not committed.
The verified candidate is now installed as `./puffer_retro_batch`; the normal
`./puffer` was preserved. Reproduce with a retained pre-change binary:

```bash
python3 ocean/retro/batch/benchmark_training.py ./puffer_retro_batch \
  checkpoints/retro_rom/retro/1789179532454/0000000065536000.bin \
  --baseline /tmp/retro-training-abba.f5geom18/baseline_puffer_retro_batch
```

Current retro defaults enable crop rendering, blocking worker handoffs,
checkpoint interval 10, and single-GPU native checkpoint-on-interrupt. At the
default batch, interval saves are 1,310,720 decisions apart (roughly 26 seconds
at this measured rate). The first Ctrl-C/SIGTERM saves after the update and
outstanding rollout complete; a second signal forces exit. These files contain
policy weights plus a configuration sidecar, **not** optimizer, recurrent or
emulator state. Unsaved work from the previous binary cannot be recovered.

## Earlier environment-only benchmark

i5-7400, four CPU cores, 1,024 environments × 128 decisions, four workers,
all 32 starts, fixed mixed run/jump/random inputs, frameskip 1, idle folding on.
`OMP_WAIT_POLICY=PASSIVE`. Initialization excluded. Both engines are selected
in the same executable, using ABBA order. The reference selection retains the
small engine-selection check in the compiled binary. Concurrent training and
other workstation activity make absolute wall throughput contended.

| Engine | Wall seconds | Process CPU seconds | Actual frames/s | Checksum |
| --- | ---: | ---: | ---: | ---: |
| Reference A | 19.039 | 30.594 | 6,885 | 413554 |
| Blocks B | 10.291 | 14.527 | 12,736 | 413554 |
| Blocks B | 9.962 | 14.395 | 13,157 | 413554 |
| Reference A | 20.225 | 28.772 | 6,481 | 413554 |

Each row executed 131,072 ROM frames and recorded zero resets. Combined:
59.366 / 28.922 = **2.05× CPU-time efficiency**, and
39.264 / 20.253 = **1.94× contended wall throughput**. This is environment
throughput, not a claim that end-to-end PPO training now achieves those ratios
or a particular uncontended SPS. A single-worker earlier iteration measured
about 1.8× CPU-time efficiency before caching the per-page cycle counter.

Reproduce:

```bash
for engine in reference blocks blocks reference; do
  OMP_WAIT_POLICY=PASSIVE build/retro_batch/retro_batch \
    bench 1024 128 4 1 all mixed 1 "$engine"
done
```

  32-level × 16-frame deterministic panel. No clears were expected or recorded.

## Remaining work

The execution fork preserves the current policy's view and controls, so it
does not itself address collision behavior or sample efficiency. GPU-scale
training requires the CPU/peripheral scheduler and mutable lanes resident on
device, with an appropriate state layout; a CPU-to-GPU round trip per emulated
I/O access would be unsuitable. Independent-core alignment and recorded
exploit tapes remain fidelity gates before claiming particular hardware
glitches, as documented in the existing realignment report.
