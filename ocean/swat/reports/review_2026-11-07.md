# SWAT correctness review, 2026-11-07

Scope: the 28 commits from `git log --since=2026-11-04 -- ocean/swat`
(519d138a5 .. 4e1be9123). I read each diff and the code around it. I focused
on sim, AI and network code (encounter, controller, sim, protocol,
door_motion, world, mission), then on render code (character_runtime,
render, lighting, environment_art, door_art_mesh, weapon_art). Tools and tests
got a lighter read.

Nothing was built or run. The only compiles were `clang -fsyntax-only` checks
of each changed file. The fixes rest on reading the code, not on tests: run
the clamber, encounter, foundation (entry replay) and tactical suites before
pushing.

Severity: **High** = sim/AI/network behaviour or determinism; **Medium** =
visible presentation error; **Low** = docs, comments or edge cases.

| 1 | High | encounter.c:712 (was `mind.clamber=clamber` in `navigation_next_actor_plan`), from bb66c3c16 | Every route request with `actor>=0` wrote `mind.clamber`, including reachability probes for other goals (`restraint_at`, `search_position`, `door_task_at`, `room_search_position_plan`). | 2 | High | encounter.c:213 `nav_clamber_edge`, from bb66c3c16 | The obstacle-top ray used `b3World_CastRayClosest` and rejected the link whenever the closest hit was not a world object. A crouched or kneeling actor, a dropped device or rubble next to a waist-high obstacle while its cells were built removed the clamber link from the shared static grid. It stayed missing until those cells were rebuilt, which only happens when an object changes. This contradicts "never bake people into the shared static nav grid", and the other static queries (`obstacle`, `floor_hit`) already skip non-world bodies. | cb276045a: a ray callback keeps the closest world-object hit. | 3 | High | protocol.c:891 `swat_apply_snapshot`, from 6cde65599 | The authority sets gravity scale to 0 when a clamber starts, and the clamber path skips `swat_body_pre_step`, which is what normally sets gravity each tick. Applying a snapshot restored `SwatMantle` but left the replica body's gravity as it was (non-zero for a walking actor). So a late-joined or resynced replica mid-clamber dropped about g·dt² per tick, including on the landing tick where velocity is zeroed, and did not converge with the authority. | fb58b37b5: zero the gravity scale when the restored mantle is active. ## Plausible, unconfirmed

| # | Sev | Where | Concern |
|---|-----|-------|---------|
| U1 | Medium | door_motion.h:26-52 `door_find_frame` / `door_frame_filter` (a11491fc0) | Static neighbours within 6 cm of a hinged leaf are put in that door's negative collision group. An object near two leaves, the floor slab in particular, keeps only the last door's group. When one door leaves hinged mode it resets the shared object's group to 0. The other hinged leaf then collides with that "frame" piece again. Framed-wall leaves keep a 25 mm undercut and the pose is projected every tick, so I could not show an actual contact. Motel leaves and jambs shared between doors are unverified. |
| U2 | Low | encounter.c:302-338 (bb66c3c16) | A partial nav rebuild re-links the dirty cells plus one ring, but clamber links span two cells. If only a link's landing cell becomes dirty, the source cell keeps a stale clamber bit. That bit can point at a now-unwalkable node, or a new link can be missed. The controller's mantle plan still validates the actual move, so the worst case is a failed jump and a replan. |
| U3 | Low | controller.c:106-121 (6cde65599) | Linear damping during a clamber is whatever the last body pre-step set, and that depends on history. A replica that applied a mid-clamber snapshot can therefore differ in the intermediate post-physics positions (hit tests, captured snapshots) until landing. Fix 3 covers the gravity part. Fixing damping would change authority behaviour, so I left it. |
| U4 | Low | encounter.c:700-711 | The clamber detection compares `at` with `from` two cells away. If the "arrived" advance loop moved `at` along a walking route that happens to end two cells from `from` along a clamber-linked line, a false positive is followed by `at=from` (walk back to the start sample) when the feet are more than 0.35 m from `from`. I did not find a concrete layout that triggers it. |
| U5 | Low | encounter.c:834 | `avoid_local_actors` can replace `mind->waypoint` with an evasive point while `mind->clamber` stays true, so the bot crouches during the sidestep. It only jumps if a wall face is within 0.7 m and 15° of that heading. This predates fix 1. |
| U6 | Low | character_runtime.c:1087-1165 | `p->transition` is a clip index into the current body's asset. If `p->body` changes mid-episode, because an earlier actor of the same role changes `present` and the rank shifts, a running transition indexes a different asset's clip list. I found no in-mission path that changes civilian or suspect presence. |
