# Text-task model and browser preset

`enter-text`, `login-user`, and `read-table` now share a CPU Bend text model in `Text.bend`. `TextWire.bend` packs it into the existing 32-lane bridge; task tags 4/5/6 route through the same compiled library as the click widgets. No new environment transitions or goal predicates are implemented in C. `text_oracle.c` is the independent Chromium comparison harness and scripted public-data controller.

The model represents exact text, selection start/end, focus, private goal strings, and terminal outcome. It supports insertion replacing the selection, Backspace, Delete, Left/Right, Home/End, select-all, focus-at-end, submit and timeout. Submission requires exact equality for every field. Existing Bend reward/deadline functions retain the original positive time scaling and negative reward behavior. The pure list model is separate from the transport limits.

The browser preset is intentionally explicit: printable ASCII, one field up to 64 characters or two fields up to 32 characters each, and insertion payloads up to 64 characters within the remaining field capacity. Unsupported transport inputs are rejected, never silently truncated. Focus-at-end performs a real mouse click followed by End; insertion uses CDP Input.insertText, and editing uses real key events, including Ctrl+A. There is no direct assignment to input values during the tested actions. This does not claim arbitrary pointer-to-caret behavior, Shift selection, Tab/Enter submission, clipboard, Unicode/grapheme/IME handling, or unbounded text.

The source audit checked the entire relevant upstream value lists against this ASCII/capacity contract: FIFTY_NAMES max 10 characters, PEOPLE_NAMES 15, LAST_NAMES 11, COUNTRIES 33, COLORS 7, GENDERS 6, LANGUAGES 10, RELIGIONS 12; all values in these lists are printable ASCII. The longest country is “Heard Island and McDonald Islands”. This is why single-field capacity is 64 rather than 32. Browser fixtures still use the original seeded generator and original reward callbacks; no independent generator for these three tasks is claimed.

The scripted controller derives goals from public quoted instructions or visible table rows. It never reads the original task's private goal closure. `read-table` observations now retain TABLE/TR context nodes so TD/TH parent references preserve row association. The full normalized DOM projection is compared after every action; caret/selection endpoints are checked separately against public input selectionStart/selectionEnd. These selection endpoints are not yet fields in the policy-facing DOM-v2 structure; they need a versioned addition when integrating the text-action preset into training. Synthetic password values are visible in this DOM preset, and are compared exactly.

Twelve text laws check in `TextLAWS.bend` / `TextPROOF.bend`: goal preservation under edits and indexed edits; preservation of values by End and select-all; unfocused editing identity; terminal/timeout absorption; deadline precedence; preservation of an unrelated tail of fields; two list lemmas; and select-all followed by insertion yields exactly the inserted text. Together with the 22 existing widget/generator laws, 34 laws check in the new-task lane. A mutation that discarded the insertion payload was rejected by the select-all replacement law. These are model properties, not proofs of the compiler, C bridge, Chromium, or the complete task specification. General reachable-state validity and Unicode edit laws remain open.

Validation passed 8,184 native edit/selection cases, plus one/two-field capacity boundaries, unchanged unrelated fields, exact multi-field submission, unfocused/invalid actions, terminal/deadline behavior, and mixed old/new task lanes. Browser validation ran 200 episodes per task, seeds 200000..200199, for 4,040 total compared actions. Schedules include correct entry, immediate wrong submission, multiple recovery/edit sequences, unfocused input, invalid target and timeout. The resulting 133 successes / 34 wrong submissions / 33 timeouts per task are scripted coverage, not learned-policy scores. These development seeds are not a held-out evaluation set.

Private wire: header words 0..11 are task, field count, focus, outcome, correctness, elapsed ms, saved elapsed ms, command, target, raw reward bits, timed reward bits, payload length. Per-field metadata at 16+4*i is value length/start/end/goal length. Values start at 32+32*i; goals at 96+32*i; payload at 160. A one-field row can use 64 units in its value/goal regions; a two-field row has two disjoint 32-unit regions. This row contains private goals and must not be used as a policy observation. Padding is cleared when values change and bridge validation rejects invalid sizes/selections before calling Bend.

The existing `webnav` trainer and watcher remain the old three-task pilot. These new task models require the new policy adapter, action/payload handling, checkpoint metadata and generators before they are a standalone training suite.
